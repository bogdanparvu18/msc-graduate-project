## Executive summary

This notebook turns the cleaned Sector 1 annotations and the completed Sector 2 alignment results into a reusable labelled-frame manifest, a decoded-video manifest, and clinical-label coverage reports. It inherits the upstream configuration, mounts persistent Google Drive storage when configured, verifies input checksums and completed alignment provenance, and preserves each accepted source annotation. Pure table transformations then validate the clinical taxonomy, decoded-frame references, bounding-box geometry, and class support. Persistence and GitHub publication are separate operations. This sector works with metadata and existing audit results; it does not decode videos again or repeat image-to-video SSIM comparisons.

The saved execution and published tables contain **47,239 annotation rows**, **47,229 distinct accepted video frames**, and **43 videos with accepted labelled evidence** within an inventory of **117 videos**. All **14 finding classes** remain represented across **9 clinical groups**, with **zero annotation rows excluded by alignment**. Of the retained annotations, **4,127 have spatially usable bounding boxes**, **43,004 have no bounding box**, and **108 have boxes extending outside the recorded video-frame bounds**. The latter remain in the manifest with explicit usability flags. The observed video-frame total is **4,765,114**, retaining Sector 2's unresolved **+23,610** difference from the configured published reference. Counts of annotations, physical-image mappings, and distinct logical frames describe different units.

## Workflow

| Stage | What the notebook does |
| --- | --- |

The annotation/frame relationship is **47,239 = 47,229 + 10**. Exactly ten frames have two annotations: nine have two different finding classes, and one has two distinct erosion boxes on the same image. These additional rows preserve meaningful annotations. Sector 2 separately records **47,238 physical-image alignment mappings**: nine multiclass frames have separate class-specific image paths, while the two erosion boxes share one image. The manifest preserves the source annotations and alignment mapping identifiers while sharing `frame_id` across annotations that refer to the same decoded frame. Per-class unique-frame counts can therefore overlap and should not be summed to obtain the global distinct-frame total.

The [`frame inventory`](reports/frame_inventory_report_20261002T004948788764Z.csv) also compares the **47,229 distinct source-frame references** with the configured **47,238 labelled-frame reference**, recording a difference of **−9**. This does not indicate nine excluded annotations: both excluded annotation rows and source-frame references without accepted evidence are zero. Reference comparisons remain visible without forcing the data to match counts expressed in a different unit. The residual relationship is **4,765,114 − 47,229 = 4,717,885** decoded frames without accepted labelled evidence.

The [`bounding-box summary`](reports/bbox_validation_summary_20261002T004948788764Z.csv) partitions all annotation rows: **4,127 + 43,004 + 108 = 47,239**. The 108 out-of-bounds annotations remain available for frame-level tasks, but their boxes should not be used for spatial supervision without a separately documented correction. Downstream code should use `bbox_spatially_usable`, rather than `has_bbox` alone, to select usable boxes. The default `require_any_bbox` and `require_valid_bbox` policies require the dataset to contain boxes and at least one usable box; they do not require every annotation to have a valid box.

The [`class distribution report`](reports/class_distribution_report_20261002T004948788764Z.csv) records 100% annotation retention for every class. Four classes have support in fewer than three videos: **ampulla of vater (1)**, **blood fresh (2)**, **blood hematin (1)**, and **polyp (1)**. These diagnostics inform later splitting but do not assign train, validation, or test membership. The video/class count matrix counts distinct accepted frames per class, so repeated annotations of the same class on one frame do not inflate it. Its binary counterpart records accepted class presence.

The saved execution reports **computed transformations**, followed by an updated catalog and successful publication to `main` in commit [`8191d4e`](https://github.com/bogdanparvu18/msc-graduate-project/commit/8191d4ee2a8563c47cfc67ef6759495c24da53e2). The publication lists **34 selected files**: **33 cataloged artifacts plus the state/catalog file itself**. This includes retained historical reports and configuration snapshots; it is not a count of 34 newly generated or changed files. Earlier timestamps on unchanged tables are intentional because persistence reuses artifacts whose content remains equivalent. The notebook source linked above was saved after that publication.

Input integrity links the confirmed annotations to Sector 2's completed attempt and final state, and links that alignment to the original cleaned metadata, physical-image inventory, and video manifest. Required confirmed/excluded outputs and the decode audit are checked against their recorded SHA-256 values, and watched inputs are checked again after loading. The excluded table is needed to verify the partition even when it contains zero rows. With `verify_all_upstream_reports=False`, unconsumed auxiliary reports do not have to be read or hashed; setting it to `True` enables the broader upstream report audit.

The transformation core accepts explicit tables and configuration, returns new tables, and performs no filesystem, network, or clock operations. Loading, storage mounting, Git operations, timestamp creation, and persistence remain in the orchestration layer. A shared canonicalization helper preserves annotation identities while keeping partition-check normalization explicit. The main manifest has one row per annotation, not one row per frame; grouping by `frame_id` is required when a downstream task needs distinct frames. Relative paths support relocation, but the referenced raw images and videos must still be available under the chosen storage root. The `opencv_frame_index` field is a compatibility alias for the aligned index, not evidence of additional OpenCV decoding.

Publication uses the final cell's `PUBLICATION_OPTIONS`. `push=False` can prepare a local commit for later publication; it is not a dry run. `dry_run=True` previews the publication plan without copying or committing artifacts. A subsequent push can resume the recorded local publication commit. Identical verified reruns avoid rewriting unchanged artifacts, and a run timestamp alone does not invalidate the transformation cache. CSV schema sidecars preserve dtypes and the explicit null marker; the detailed bounding-box report is gzip-compressed. The local publication receipt is operational state and is excluded from the GitHub artifact bundle.

The current table-fingerprint implementation has a known edge case: a missing `None` and the literal text `"None"` in an object column can receive the same table fingerprint. This affects change detection and requires a versioned fingerprint correction; it is separate from file-byte SHA-256 verification. The reviewed domain tables matched local recomputation, and this edge case was not observed in their published results. Clinical-group checks verify consistency with the inherited mapping, not independent medical correctness. Frames without accepted labels are not automatically negative, and the upstream frame-count discrepancy remains open. This sector does not crop images, repair bounding boxes, create splits or temporal windows, train models, or perform medical question answering.
