## Executive summary

This notebook assigns reproducible train, validation, and test membership to the accepted labelled frames produced by Sector 3, summarizes each video's split memberships and role, and creates sampled unlabelled frame references for later domain adaptation. It inherits the current verified Sector 3 configuration, declares its own split and adaptation settings, and separates pure table transformations from input loading, persistence, and GitHub publication. The split unit is a unique decoded frame: all annotations belonging to the same `(video_key, opencv_frame_index)` receive one assignment. Videos may participate in several supervised splits. Every finding class must have at least the configured minimum number of frames in each split.

The saved execution retains **47,239 annotation rows** belonging to **47,229 distinct labelled frames** from **43 videos**, within the **117-video** upstream inventory. Train contains **33,060 frames**, validation **7,084**, and test **7,085**; all **14 finding classes** occur in every split. All 43 labelled videos have mixed supervised membership and are excluded from adaptation. The remaining **74 fully unlabelled videos** contribute **185,755 sampled frame references**. Sector 4 prepares these references and assignments; it does not decode videos, extract images, train a model, or perform domain-adaptation learning.

The transformation core receives explicit tables and configuration and returns new tables without filesystem, network, or clock operations. Loading, storage mounting, timestamp creation, persistence, recovery, and Git publication remain in the orchestration layer. S4 verifies and consumes S3 outputs; it does not repeat Sector 2 decoding or image alignment. The `opencv_frame_index` column is the existing compatibility alias for `aligned_frame_index`, equal to it throughout the accepted manifest. The reviewed upstream video inventory records NVIDIA NVDEC decoding; the alias name does not imply CPU or OpenCV decoding in this sector.

Downstream consumers must join supervised assignments through `(video_key, opencv_frame_index)` or the corresponding verified frame identity. The video membership table cannot be converted into a single `video_key -> split` lookup. The labelled manifest remains annotation-level, while the frame manifest is frame-level. Later segment construction and temporal-context selection must preserve those assignments. Shared-video evaluation measures held-out frames from videos also represented in training; it does not establish independent-video or independent-patient generalization, and temporal similarity can affect measured performance.

Persistence verifies both file-byte SHA-256 values and typed table content. On a healthy identical rerun, unchanged files retain their existing contents and timestamps. Changed configurations or relevant provenance produce new snapshots; normal report changes retain timestamped versions. Missing or invalid S4 outputs can be rebuilt from verified S3 inputs. Recovery stages and checks a complete replacement before moving the prior directory aside; installation errors trigger rollback. Invalid S3 inputs, access failures, and computation errors remain failures. Recovery copies stay outside the active S4 directory and are not selected by the publisher. The active catalog is rebuilt during recovery, while the prior directory preserves the previous bundle.

Publication is controlled by the notebook's `push` and `dry_run` settings. With `push=False` and `dry_run=False`, the final cell skips publication. `dry_run=True` prepares and checks the proposed changes in a temporary checkout, including copying files and inspecting the Git diff, without committing or pushing; it does not disable the earlier local-persistence cell. Publication uses an isolated checkout, checks the active catalog and copied files, and avoids a new commit or push when the selected Git content is unchanged. It still performs verification and repository preparation. This README is outside the generated artifact catalog and is maintained independently.

The reviewed revision has two known maintenance issues: `recover_invalid_outputs` is placed under `github_overrides`, although the recovery helper reads the Sector 4 settings, so recovery currently relies on its default `True`; changing only the generated executive-report text can fail because its temporary `reports/` parent is not explicitly created. Repeated table reads and unused notebook-level lookup calculations also remain opportunities for simplification. These issues did not invalidate the published results checked for this report. The SHA-256 and typed checks detect ordinary persisted-file damage, while semantic validation could be extended to compare all derived reports, annotation totals, and video-path mappings across tables. Unlabelled references are not verified negative examples. This sector does not repair inherited bounding boxes, create temporal segments or windows, extract image assets, generate pseudo-labels, train models, or perform medical question answering.
