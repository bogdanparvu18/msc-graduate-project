## Executive summary

This notebook groups temporally adjacent verified frames of the same finding class within each video into finding segments. It consumes the checked Sector 2–4 artifact chain, preserves Sector 4's existing physical-frame train, validation, and test assignments, and keeps every accepted source annotation. Segments receive reproducible identifiers, observed frame limits, a representative verified frame, and an explicit temporal-supervision level. Pure table transformations remain separate from input loading, Google Drive persistence, recovery, and GitHub publication.

The saved execution retains **47,239 annotation rows**, representing **47,238 distinct frame/class anchors** on **47,229 physical frames** from **43 labelled videos**. These become **22,220 finding segments**: **13,378 single-frame anchors** and **8,842 multi-frame weak-supervision candidates**. All **14 finding classes** remain represented in each supervised split. Sector 5 organizes the available verified evidence; it does not establish exact clinical onset or offset, prove continuous visibility between anchors, extract images, or train a temporal-grounding model.

## Workflow

| Stage | What the notebook does |
| --- | --- |
| Configuration and storage | Locates the current Sector 3/4 catalogs and completed Sector 2 artifacts through `BOOTSTRAP`, mounting Google Drive when configured. It inherits the verified Sector 4 configuration and resolves two Sector 5 algorithm settings: currently **`segment_max_gap_frames=1`** and **`minimum_verified_segment_frames=2`**. Their inheritance/default decisions are recorded in the provenance snapshot. |
| Validated input loading | Checks upstream completion, catalog identities, file sizes and SHA-256 values, typed table fingerprints, and the S2 → S3 → S4 consumed-input chain. It compares accepted annotation identities and multiplicities, verifies decoded-frame bounds, and checks S4's authoritative frame assignments against the labelled and video/split manifests. Runtime media paths are rebased after persisted-input validation. |
| Annotation-preserving segmentation | Builds distinct temporal anchors within each video and normalized finding class while retaining all annotation rows. A segment starts at the first anchor, a source-frame gap exceeding the configured limit, or an observed split-run change. Split runs are derived across all accepted physical frames in each video before grouping by class, preventing a segment from joining across an intervening observed assignment to another split. |
| Segment identities and representative evidence | Creates collision-checked ordinal identifiers in the form `video__class__00001`. Each segment records its observed start/end, verified anchor count, annotation count, and split. Its target is the middle verified anchor in temporal order, using the upper middle for even counts. Associated image references and annotation/bounding-box metadata are retained without selecting by image quality or preferring a usable box. |
| Supervision and support reporting | Marks one-anchor segments as `single_frame_anchor_only`. Segments meeting the configured anchor threshold with a nonzero observed span become `multi_frame_weak_supervision` candidates; other multi-anchor cases are insufficient. Clinical boundary availability remains false. A split/class report counts anchors, videos, and segments independently and includes zero-support combinations when present. |
| Calculation identity and persistence | Calculates the transformation chain once in Section 11 and binds the results to the verified input fingerprint, active core code, dependency versions, and relevant settings. Before saving, it rejects changed result tables, stale processing signatures, or changed upstream artifact bytes. It writes and verifies manifests, schemas, provenance, reports, and the S5 catalog, reusing unchanged saved content. With `recover=True`, invalid S5 outputs can be rebuilt from freshly calculated results and verified upstream inputs. |
| GitHub publication | The separate publication cell verifies the saved bundle, copies selected files into an isolated checkout, checks their bytes, and commits changes under `outputs/phase2/sector5/`. Unchanged selected Git content produces no new commit or push. This README is maintained separately from the generated artifact catalog. |

The transformation core receives explicit tables and configuration and returns new tables without filesystem, network, or clock operations. It uses CPU table processing with NumPy, pandas, and PyArrow; no video or image decoding occurs in S5. The current provenance records versions **2.1.3**, **2.2.3**, and **23.0.1**, respectively. The loader checks the whole upstream catalogs but materializes only the required S4 labelled-frame, frame-split, and video/split tables; S4's domain-adaptation manifest, domain-source videos, and video-role manifest are not loaded as DataFrames by S5. S3 class-support tables are still read for the existing input contract. `opencv_frame_index` is an inherited decoded-frame identity, not evidence of OpenCV decoding in this sector.

Downstream consumers should use `finding_segment_id` to join segment summaries to their complete annotation members and preserve the associated split. Segment identifiers are ordinal and reproducible for unchanged inputs and grouping policy; adding or removing an earlier segment can renumber later identifiers. For a target with several same-class annotations, the manifest retains the annotation list and box metadata in JSON fields rather than inventing a merged box. A segment summary must not replace the full member table when all annotations are needed. Temporal-window planning and extraction belong to later sectors.

The processing signature is captured when the result tables are calculated. It incorporates consumed upstream hashes, the fingerprint of the normalized and rebased source table, the active transformation code and referenced constants, dependency versions, relevant processing settings, and the runtime storage root. Saving compares this identity and the output table fingerprints with the current state and rechecks upstream bytes. Modifying inputs, processing settings, active core functions, dependencies, or result tables requires the appropriate reload/recalculation before saving. The catalog's dependency-version copy is also checked against the protected configuration snapshot when present; legacy catalogs without that field remain readable.

Persistence verifies file-byte SHA-256 values and typed table content. On a healthy identical rerun, unchanged saved files retain their contents and timestamps, although the notebook's normal Section 11 path still calculates the transformations; the optional checked-cache loader is not invoked by that path. Changed processing provenance refreshes the configuration snapshot even when result tables remain identical. With the current save cell's `recover=True`, missing or corrupt S5 generated outputs are rebuilt in a staging directory from fresh results. The previous `configs/`, `results/`, and `reports/` directories are retained under a sibling `.sector5-recovery-*` directory before replacement, with verification and rollback support. Root-level files such as this README remain in place. Invalid upstream inputs, access failures, and computation errors remain failures; S5 recovery does not repair S2–S4 artifacts.

Publication is controlled by `push` and `dry_run`. With both false, no publication is requested. A dry run prepares and checks the proposed changes without committing or pushing; it does not disable the earlier local save. With `push=True`, a commit is created only when selected Git content differs. The publisher checks source and copied file bytes, while the final change decision comes from the staged Git diff. It does not independently compare SHA-256 values of staged Git blobs after Git clean filters or line-ending transformations. This README is outside the generated catalog and is maintained independently.

The principal interpretation limit is inherited from S4: the same labelled videos participate in training and evaluation, so these outputs do not establish independent-video or independent-patient generalization. Nearby frames can remain highly similar across splits, and frame-level assignments create many short segments. A larger gap setting would permit unknown intermediate frames within an observed span; their visibility and labels must not be inferred from the endpoints. S5 does not repair inherited bounding boxes, track individual lesions, establish continuous clinical boundaries, regenerate upstream sectors, create adaptation samples, extract temporal image windows, train models, or perform medical question answering.
